# Finance Tracker

REST API для учёта доходов и расходов и полноценный QA-портфолио-проект: тестовая стратегия, автотесты на Go, OpenAPI, Postman, Docker и CI/CD.

## Что проверяет проект

- регистрацию, нормализацию email и bcrypt-хеширование пароля;
- логин и Bearer-аутентификацию;
- защиту от доступа к ресурсам другого пользователя;
- создание и получение счетов и категорий;
- полный жизненный цикл транзакции;
- фильтрацию по типу, счёту, категории и периоду;
- пагинацию и стабильную сортировку;
- месячные отчёты по доходам, расходам и балансу;
- строгий JSON-контракт, HTTP-коды и типы содержимого.

Суммы передаются целыми числами в минимальных денежных единицах: например, `250000` означает 2 500,00 RUB.

## Архитектура

```text
Go HTTP-клиент / Postman → роутер chi → промежуточный обработчик Bearer → обработчики API → потокобезопасные хранилища в памяти
```

Данные и токены хранятся в памяти и сбрасываются при перезапуске. Это осознанное ограничение текущей версии: проект фокусируется на API-тестировании, а не на инфраструктуре базы данных.

## Автоматизация

### Интеграционные тесты на Go

`cmd/api/api_test.go` создаёт изолированный экземпляр приложения и проверяет маршруты через `httptest`:

- позитивные и негативные сценарии;
- граничные значения;
- фильтрацию и отчёты;
- права владения ресурсами;
- стабильность коллекций;
- жизненный цикл транзакции.

Текущее локально подтверждённое покрытие операторов: **70,3%**. Детектор гонок запускается в Linux CI; локальный контроль качества PowerShell включает его автоматически, когда доступен CGO.

```powershell
go test -v ./cmd/api
go test -race -coverprofile coverageprofile -covermode atomic ./cmd/api
```

### API-тесты на Go по методу чёрного ящика

Независимый набор в `tests/api` использует стандартные пакеты Go `testing` и `net/http` и автоматически:

1. выбирает свободный localhost-порт;
2. собирает и запускает API как отдельный процесс;
3. ожидает готовность `/health`;
4. выполняет HTTP-проверки только через публичный контракт API;
5. проверяет документ OpenAPI библиотекой `kin-openapi`;
6. завершает процесс после набора тестов.

```powershell
go test -v ./tests/api
```

## Быстрый запуск

Требования: Go 1.26+.

```powershell
go run ./cmd/api
```

Проверка:

```powershell
Invoke-RestMethod http://localhost:8080/health
```

Другой адрес можно задать переменной:

```powershell
$env:HTTP_ADDR = "127.0.0.1:9090"
go run ./cmd/api
```

## Docker

```powershell
docker compose up --build
```

После запуска API доступен по адресу `http://localhost:8080`. Compose проверяет `/health`.

## Postman и OpenAPI

- `api/openapi.yaml` — валидируемый контракт OpenAPI 3.1;
- `postman/Finance-Tracker.postman_collection.json` — последовательный дымовой сценарий;
- коллекция сама сохраняет `userId`, `token`, `accountId`, `categoryId` и `transactionId` из ответов.

Импортируйте коллекцию в Postman и запускайте запросы сверху вниз средством запуска коллекций.

## CI/CD и контроль качества

Сценарий `.github/workflows/ci.yml` выполняет три независимые задачи:

1. форматирование, `go vet`, детектор гонок и измерение покрытия Go-кода;
2. регрессионные API-тесты на Go по методу чёрного ящика и проверку OpenAPI;
3. сборку Docker-образа и дымовую проверку контейнера.

Локальный запуск основных проверок:

```powershell
.\scripts\quality-gate.ps1
```

## Найденные дефекты

Во время анализа исходной версии были обнаружены и исправлены:

- нарушение контроля доступа через подстановку `user_id`;
- принятие неизвестных JSON-полей;
- недетерминированный порядок элементов из map в Go;
- отсутствие проверки email и минимальной длины пароля;
- непоследовательные ошибки валидации;
- принятие JSON без правильного `Content-Type`.

Для каждого дефекта добавлена регрессионная проверка. Подробности — в [BUG_REPORTS.md](docs/qa/BUG_REPORTS.md).
