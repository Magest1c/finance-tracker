# Тест-дизайн

## Разбиение на классы эквивалентности

| Входные данные | Валидные классы | Невалидные классы |
|---|---|---|
| `user_id`, идентификаторы ресурсов | Положительные целые числа | Отсутствующее значение, ноль, отрицательное или нецелое значение |
| Тип транзакции `type` | `income`, `expense`, пустое значение фильтра | Любая другая строка |
| Валюта | Три буквы с приведением к верхнему регистру | Пустое значение, меньше или больше трёх символов, небуквенные символы |
| Email | Корректный адрес почтового ящика | Отсутствующий или некорректный адрес |
| Тело JSON | Один объект с известными полями | Некорректный JSON, несколько значений, неизвестные поля, превышение размера |
| Bearer-токен | Токен, выданный сервером | Отсутствующий заголовок, неверная схема, неизвестный токен |

## Анализ граничных значений

| Поле | Проверяемые границы |
|---|---|
| Длина пароля | 7 — невалидно, 8 — валидно |
| Сумма транзакции | 0 — невалидно, 1 — валидно |
| Лимит пагинации | 0 — невалидно, 1 и 100 — валидно, 101 — невалидно |
| Смещение пагинации | -1 — невалидно, 0 — валидно |
| Длина имени | 0 — невалидно, 100 — валидно, 101 — невалидно |
| Размер тела запроса | До 1 МиБ — валидно, больше 1 МиБ — невалидно |
| Диапазон дат | `from < to` — валидно, `from = to` и `from > to` — невалидно |

## Таблица решений: доступ к защищённому ресурсу

| Токен | Запрошенный `user_id` | Владелец ресурса | Ожидаемый результат |
|---|---:|---:|---|
| Отсутствует или невалиден | Любой | Любой | 401 Unauthorized |
| Пользователь A | Пользователь B | Любой | 403 Forbidden |
| Пользователь A | Пользователь A | Пользователь B | 403 Forbidden |
| Пользователь A | Пользователь A | Пользователь A | Выполнение операции продолжается |
| Пользователь A | Пользователь A | Ресурс отсутствует | 404 Not Found |

## Переходы состояний транзакции

```text
не создана -> POST /transactions -> активна
активна -> PATCH /transactions/{id} -> активна (изменена)
активна -> DELETE /transactions/{id} -> удалена
удалена -> PATCH или DELETE -> 404
```

## Модель временного интервала

Запросы транзакций и месячные отчёты используют полуинтервал: `from <= occurred_at < to`.

- транзакция точно в начале месяца включается;
- транзакция точно в начале следующего месяца исключается;
- соседние месячные отчёты не могут дважды учесть одну транзакцию.

## Проверки тестового оракула для ошибок

- при неизвестном email и неверном пароле вход возвращает одинаковую ошибку;
- ошибки JSON имеют единый формат: `{"error":"..."}`;
- ответ 204 после удаления не содержит тела;
- успешные ответы и ошибки используют `application/json`, кроме ответа 204.
