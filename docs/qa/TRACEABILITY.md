# Трассировка требований

| Ожидание от QA-стажёра | Подтверждение в репозитории |
|---|---|
| Методы и подходы тестирования | `TEST_PLAN.md`: многоуровневая стратегия, позитивные, негативные тесты, проверки безопасности и контракта |
| Техники тест-дизайна | `TEST_DESIGN.md`: классы эквивалентности, границы, таблица решений и переходы состояний |
| Баг-репорты и приоритизация | `BUG_REPORTS.md`: серьёзность, приоритет, воспроизведение и исправление |
| Код на одном из подходящих языков | Go-приложение, интеграционные и black-box тесты на Go |
| Автоматизация UI или API | API-фреймворк чёрного ящика на Go с `testing` и `net/http` |
| Понимание процесса разработки ПО | Цикл «дефект → регрессионный тест → исправление → полный контроль качества» |
| Основы сетей | HTTP-методы и статусы, заголовки, Bearer-аутентификация, типы содержимого, локальные порты, RFC3339 |
| Знание SQL | Текущая версия намеренно использует память; PostgreSQL и интеграционные SQL-тесты запланированы следующей итерацией |
| Принципы CI/CD | GitHub Actions запускает форматирование, статический анализ, тесты гонок данных, измерение покрытия, проверку контракта и дымовый тест Docker |
| Инструменты тестирования API | Контракт OpenAPI 3.1 и коллекция Postman |
| Контейнеризация | Многоэтапная сборка Docker и проверка состояния через Compose |

## Честное ограничение

Проект пока не демонстрирует тестирование базы данных. Следующая содержательная итерация — PostgreSQL, миграции и интеграционные SQL-тесты. Это честнее, чем заявлять знание SQL без подтверждения в репозитории.
