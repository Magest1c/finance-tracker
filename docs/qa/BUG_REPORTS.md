# Обнаруженные и исправленные дефекты

Дефекты были найдены при анализе и тестировании исходной копии проекта. Каждое исправление защищено регрессионными тестами.

## FT-001: Нарушение контроля доступа через передаваемый клиентом `user_id`

- Серьёзность: Критическая (Critical)
- Приоритет: P1
- Статус: Исправлен
- Компонент: Аутентификация и авторизация

Шаги воспроизведения:

1. Зарегистрировать пользователя A и создать его счёт.
2. Зарегистрировать пользователя B.
3. Запросить `/accounts?user_id=<id-пользователя-A>` без подтверждённой сервером личности вызывающего пользователя.

Фактический результат исходной версии: API доверяет `user_id` и возвращает данные пользователя A.

Ожидаемый результат: сервер должен определить личность вызывающего пользователя и отклонить доступ к чужим ресурсам.

Исправление: добавлены криптографически случайные Bearer-токены, промежуточный обработчик аутентификации и проверка соответствия владельца токена, запрошенного пользователя и владельца ресурса.

## FT-002: Неизвестные поля JSON принимались без ошибки

- Серьёзность: Серьёзная (Major)
- Приоритет: P2
- Статус: Исправлен
- Компонент: Контракт API

Пример: регистрация принимала `{"is_admin":true}`, хотя поле отсутствует в модели запроса. Это скрывает ошибки клиента и ослабляет контрактное тестирование.

Исправление: реализован единый декодер JSON с `DisallowUnknownFields`, проверкой единственного объекта и ограничением тела размером 1 МиБ.

## FT-003: Порядок счетов и категорий был недетерминированным

- Серьёзность: Серьёзная (Major)
- Приоритет: P2
- Статус: Исправлен
- Компонент: Коллекции

Фактический результат исходной версии: элементы возвращались напрямую из Go map, поэтому повторные запросы могли выдавать разный порядок.

Ожидаемый результат: стабильный документированный порядок, не создающий нестабильности клиентов и тестов.

Исправление: счета и категории сортируются по возрастанию `id` перед сериализацией.

## FT-004: При регистрации принимались некорректный email и слабый пароль

- Серьёзность: Серьёзная (Major)
- Приоритет: P2
- Статус: Исправлен
- Компонент: Валидация входных данных

Фактический результат исходной версии: в качестве email и пароля принимались любые непустые строки.

Исправление: добавлена проверка синтаксиса email, минимальная длина пароля восемь символов и ограничение имени до 100 символов.

## FT-005: Несогласованные сообщения об ошибках аутентификации

- Серьёзность: Незначительная (Minor)
- Приоритет: P3
- Статус: Исправлен
- Компонент: Контракт ошибок

Фактический результат исходной версии: для похожих некорректных запросов входа использовались разные язык и формулировки.

Исправление: стандартизированы сообщения и структура ошибок. Неизвестный email и неверный пароль намеренно возвращают одинаковый ответ, чтобы затруднить перебор учётных записей.

## FT-006: JSON-маршруты не проверяли тип содержимого

- Серьёзность: Серьёзная (Major)
- Приоритет: P2
- Статус: Исправлен
- Компонент: Протокол HTTP

Фактический результат исходной версии: тело запроса принималось без `Content-Type: application/json`.

Исправление: JSON-маршруты возвращают 415 Unsupported Media Type, если тип содержимого отсутствует или указан неверно.
